THE VOID THRONE — ONLINE MULTIPLAYER

Start or join
Everyone opens https://jkeywo.github.io/void-throne/. The facilitator chooses Start a new game and shares the room code. Each player enters that code, their name and requested seat, then chooses Join the table. The facilitator admits each player. You need five players and one facilitator, each with their own browser. No local game server or Python installation is needed.

The first host visit downloads the game engine. Keep the facilitator's tab open throughout play. Players submit their own sheets and signatures; the facilitator closes phases and records the exact proposals. Timings are displayed but discussions do not close automatically. Rules and faction briefs are available from the buttons at the top. Conversations support table, faction, council and private facilitator channels. There is text chat but no built-in voice or video.

Resume and save
The host's browser saves after every accepted change, before sending the resulting state to players. After closing or reloading the page, return in the same browser to the same website and choose Resume saved game. The room code, seats, submitted sheets, history and private visions are restored. Players can reconnect with their saved seat; if they are still waiting, use Reconnect. Only one tab per browser can host, to prevent conflicting saves. Closing a hosting tab releases that protection.

If a player changes browser or machine, release their old seat and admit the replacement. Releasing a seat discards that seat's unclosed sheet and reconnect key. Earlier decisions remain recorded. Unsaved player form entries are retained locally where browser storage is available.

Starting a new game archives the old save in the same browser and generates a new code. Download host backup or Download archived backups keeps a copy outside browser storage. These files contain private information and reconnect keys; keep them to yourself. There is no backup import screen yet. Clearing site data or using a temporary browsing session can lose saves. If autosave fails, stop play and download the recovery backup before closing the tab.

Record the playtest
Download HTML report produces the phased transcript, side-by-side sheets, mechanical results and tabs for parallel conversations. Download decisions and chat produces the JSON record without reconnect credentials. These facilitator records include private visions and conversations. No playtest data is uploaded to GitHub Pages.

Connections
PeerJS 1.5.5 uses its public signalling service, then WebRTC carries messages between browsers. Hosting also loads Pyodide 314.0.7 from jsDelivr. Internet access is required. Restricted networks may need an organiser-supplied TURN relay or private PeerServer. Put the supplied PeerJS options in Connection settings on every machine; those options are remembered by the browser. Do not use localhost settings for remote players. Connectivity on one network does not guarantee all corporate networks will connect.

Privacy and source code
The repository and scenario code are public. Players should avoid inspecting hidden conditions if they want to experience foresight during play. Live private information is still filtered for each seat before transmission. Host saves remain in the facilitator's browser; players receive only their authorized view. The page does not offer an anti-cheat guarantee against people reading the public rules engine.

Older local sessions
The original all-seat test bench remains separate. Start Multiplayer.cmd serves this same unified interface locally. Browser saves belong to their exact website address, so a game started on localhost does not appear on the hosted website. Older .playtrace/multiplayer-session-PORT.json files remain on disk but are not automatically imported.
