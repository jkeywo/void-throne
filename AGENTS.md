# The Void Throne

The game is a paper design. The browser and Playtrace are development tools.
Current scope: five players, one facilitator, two operational rounds, weighted settlement and three starting foresight tokens. Preserve actual choices in archived transcripts.

## Authority
The native Drive rulebook, Player Briefs, Component Reference and facilitator guide are the editable design documents. `design/drive-files.json` records their IDs and the captured revision. Local `docs/` files are the initial publication source and offline copies, not an automatic two-way sync. Read current Drive documents before publishing revisions. Update the engine and tests when rules change; never silently make code authoritative over an edited document.
Historical sources in `archive/` are read-only provenance. `lore/` separates source lore, user corrections, scenario inventions and unresolved questions. Do not restore obsolete individual goals, Clarity, a strategic map or unanimous final ratification.

## Implementation
Game code stays in this repository. Playtrace remains a dependency at `C:/Coding/playtrace` (override with PLAYTRACE_ROOT). Register the game plugin; do not put game-specific material in the shared system. `python playtrace_game.py reproduce` creates snapshots, deterministic replay, report and hypothesis-linked evidence. `python launch.py` opens the local all-seat browser test. `python -m unittest discover -s tests -v` checks rules and complete-session behavior.
The original all-seat browser is a facilitator test bench: one person controls all five seats. It does not simulate human bargaining or run live LLM opponents. Exported browser traces and the preserved six-agent transcript are distinct evidence types. New agent simulations must use scoped information and preserve original authored decisions.

The PeerJS multiplayer interface is a separate human-seat mode. Keep seat authorization and private projections in `multiplayer.py`; never send `Session.public()` or raw actions to player peers. Each remote player submits their own decisions; matching browser card placements confirm agreement without a separate signature; paper play uses the cards themselves and no faction decision sheet. Current council programmes need assets, not approval from the authority holder. Provisional article assent still applies. Final settlement uses assent tick boxes. Only the facilitator closes phases. Legacy actions containing a signatures field retain their historical gate when replayed; new actions omit it. Rebuild portable HTML with `tools/build_multiplayer.py` after changing multiplayer sources or bundled public documents.

The unified online page hosts the existing Python authority in a Pyodide module worker. Keep browser entry points in browser_host.py fixed; remote peer messages must go through Multiplayer.receive. Persist host backups in IndexedDB before broadcasting accepted results, and hold the browser Web Lock while hosting. Both multiplayer HTML filenames must be identical. The repository and scenario code are public; live private state still requires explicit seat projections.

Faction phases: teammates confer privately from the start. The Ascendant chooses a prophecy or NONE before receiving current faction plans or visiting either faction. Covers name councils only; specifics remain in paid answers. Visits then precede locked assignments. Current browser sessions choose foresight directly from the draft stage; legacy draft/proposal actions remain replayable. Restrict faction-phase chat on the host and do not leak private drafts through history.

During council phases, players remain at their assigned table (GN/JN at Navigation; GS/JS/A at Security). Block cross-council, teammate and table messages and working-sheet leaks. GN records Navigation allocations (including offered Grey Petrel); JS records Security allocations. The Ascendant remains at Security and submits only their Warrant there. Reveal both final programmes together. Authority sets next-round vetoes during the Free Phase; it does not choose current orders.

Player materials conceal exact operational modifiers, thresholds and resolution order. Keep asset ownership, requirements, purpose, qualitative risk, Charter duties, track values/descriptions, foresight purchase cost and settlement voting public. The facilitator guide and private-cards contain exact resolution rules; player-visions contain qualitative conditional handouts. Multiplayer peers receive presentation.public_resolution and player_vision, never the raw effect ledger, private answer arithmetic or resolution inputs/detail. The all-seat bench and facilitator exports remain full diagnostic views.

Current v0.4 lives in current_session.py and orders_v04.py. session.py and operations.py preserve v0.3 replays. Start new browser games with the current class; restore according to the saved ruleset. Each printed order and asset is used once. Lantern carries civilian relief only; Wayfarer and Grey Petrel can carry civilians or troops. Grey Petrel is a component, has one contracted service, and cannot rescue and transport together. Either/both funded transport orders produce one Beacon wear even if halted; private commercial wear remains separate. Joint authority grants one veto per contributing party in each Joint domain, based on any available asset offered to either council during the completed round. Prior authority sets vetoes before new articles; existing vetoes persist through article changes. Do not silently claim the two-round prototype tests new articles’ following-month vetoes.

Asset cards: Spear has Stand Down / Intercept a Patrol home faces; Grey Petrel has Retain the Cutter / Protect the Navigators. Other assets have one home action. Location chooses home or printed council; a home face has no effect at council. Public traits in assets.py govern order eligibility in the engine and both UIs. Traits do not grant extra uses. Named Charter obligations and prophecy conditions remain specific. Preserve archived v0.4 action encoding; this presentation/eligibility refactor changes no existing combination or outcome.
